# ADR-003｜WatchPilot Lab台灣OTT片庫IN／OUT觀測雷達

## 決策摘要
PR #3在PR #2（TW電影查詢與片源研究）之上新增單人、Local-first的片庫雷達。

**研究範圍：只追蹤使用者自己加入的少量電影，不進行整庫爬蟲或持續背景掃描。**

## 實作流程
1. 在`/lab/tw`以TMDB查詢電影，按「加入雷達」。
2. 存下該電影的少量片源欄位與時間戳，建立BASELINE事件；**首次收錄不等於新上線**。
3. 在`/lab/radar`手動按「重新查詢」，一部片一次呼叫兩個TMDB API：電影詳情及觀看來源。
4. 正常查詢的成功快照才用於比較；失敗僅新增SOURCE_FAILED稽核，不得替換為空的成功結果。
5. 每次比對依同平台不同觀看權益，產生NEWLY_OBSERVED／ACCESS_CHANGED／MISSING_FIRST／MISSING_REPEATED／RETURNED_OBSERVED等觀測事件。
6. 使用者核對官方公告URL、平台與日期後可另外新增人工下架期限紀錄；期限與片源可用性是**獨立證據維度**。
7. 觀影重新規劃採取最新可用資料，依每日／每週觀看上限、偏好、期限重新排程並比較新舊結果。

## 可信度與警示
- `BASELINE`：建立首次有效觀測，不表示當天上架。
- `NEWLY_OBSERVED`：比上一次有效觀測多了觀看來源，**不等於官方新上架日**。
- `MISSING_FIRST`：來源中第一次缺失，**不等於下架**。
- `MISSING_REPEATED`：兩次缺失且至少相隔24小時，仍**不等於版權到期或官方確定下架**。
- `SOURCE_FAILED`／`SOURCE_PARTIAL`：不納入成功片源差異。
- `ACCESS_CHANGED`：訂閱、免費、租借、購買等權益變化，不能等同平台轉移或授權結束。
- `USER_REVIEWED_OFFICIAL`：**使用者自行核對後標記**的下架日；系統沒有替使用者向平台驗證。會影響排程有效日期，但不得變更TMDB片源本身的`OBSERVED`等級。

## 資料與隱私
- 只在使用者瀏覽器localStorage儲存，無中央帳號／共享資料庫。
- 每次片源儲存僅含作品識別碼、必要片長與評分欄位、平台ID、存取類型、資料來源時間。
- 最多20部追蹤電影；每部最多20筆快照，且只保留30天內快照。
- 不在GitHub提交真實片庫快照、API Key或個人訂閱紀錄。
- 假資料演練以`FIXTURE`標示，不寫入真實雷達。
- 仍需遵守TMDB、JustWatch及其他第三方資料來源的使用條款。
- 本機原型可使用，**不得將查詢API直接對公網開放**。公網版本需認證、速率限制及重新審查資料權利。

## 非目標
- 自動宣稱官方下架／版權到期。
- 自動背景爬蟲、推播通知、監控所有台灣OTT節目。
- 提供第三方資料轉售或大規模匯出。
- 保證全域最佳觀影排程（目前使用Greedy Baseline）。

## 後續研究
1. 由研究者實際提供TMDB Key，針對至少20部台灣影視作品做官方OTT交叉驗證。
2. 測試同片名、不同TMDB ID、不同平台權益變化的誤報率。
3. 對真正有公開下架清單的OTT建立官方來源Adapter及定期合法更新。
4. 需要長期持久化與多裝置時，再評估SQLite／IndexedDB與資料契約。
